# DSH-TASK-IMPORT-FILES：言语词库支持 PDF、Excel、图片、Word 导入

## 目标

文轩要求：言语词库可以通过 **PDF、Excel、图片、Word** 等方式导入词条。

现状：「我的词库 → 导入词表」只接受 CSV/TXT/TSV/JSON 和粘贴；Excel 还得先另存为 CSV。上传入口现在用 `FileReader.readAsText`，二进制文件读不了。

- 不删用户数据；不提交 `node_modules/`、`data/app-data.json` 及 backups、`.env`、密钥、`.wrangler/`、本机数据。
- 不要改公考错题本仓库；不要拆除已上线的 Cloudflare 登录版（https://yanyu-cishu.cishu-3466556309.workers.dev/ ），它与 GitHub Pages 静态版并存。
- 不要占用或关掉文轩电脑上公考错题本的 8080。
- 不扩范围：不要做「导入整份备份」、不要改练习/登录/同步逻辑，不要借机大改界面。
- 界面继续用白话。若必须再授权或必须花钱，立刻停下，把原因写进验收文档并结束本轮，等待拍板。

## 产品要求

1. 在现有「导入讲义或词表」里，可以直接选这些文件（手机/平板也能从相册选图片）：
   - Excel：`.xlsx`，尽量同时支持旧的 `.xls`
   - Word：`.docx`（旧的 `.doc` 若不好做，用白话提示另存为 Word 或 PDF，不要静默失败）
   - PDF：能提取文字的 PDF；扫描件（整页是图）按图片同样做识字，能用即可，不必完美
   - 图片：`.jpg` / `.jpeg` / `.png` / `.webp`，以及常见截图
   - 原有 CSV/TXT/TSV/JSON 和粘贴必须照常可用
2. 导入只进当前使用者自己的词库（Pages 版只进当前浏览器；Cloudflare 登录版只进当前账号），别人看不到。
3. 冲突规则不变：成语、实词都是「同一类型 + 字面完全一样」才算冲突；只跳过冲突的那几条，其余照常导入，不覆盖已有词。
4. 表格类（Excel，或 Word/PDF 里的表）按现有表头规则识别（类型、词语、释义、例句、来源、近义、干扰；中英文别名沿用 `importer.js`）。没有表头时，合理猜测列（词语、释义等），不要整表丢弃。
5. 讲义/照片等非表格内容：尽量从正文里抽出词条（常见形态如「词语 + 释义」、四字成语带解释、分行列出的词表）。类型没写时：四字优先当作成语，其余当作实词。没有释义的不要强行入库，放到「未能导入」里用白话说明。
6. 识别结果先给预览，再让使用者确认导入。预览里写清：将导入多少条、跳过多少条（重复或不合格）及原因。识字或排版不准时，允许使用者在确认前改词语、类型、释义，或去掉某条。
7. 读文件、识别过程中用白话提示「正在读取 / 正在识别」，失败时说明是文件打不开、不是词表，还是没认出字，并给出可做的下一步（例如换清晰一些的照片，或改用表格）。
8. 一次先处理一个文件，做到可用即可。

## 技术要求

- 前后端分离的前端在 `public/`，Pages 静态版和 Cloudflare 登录版共用。改动必须两头都能用：Pages 版完全在浏览器本地完成，不能依赖 Node 服务或 Worker 接口。
- 第三方库必须免费、许可证允许进公开仓库；优先放进本仓库（或构建产物）以便 PWA 缓存后离线还能导入已缓存过的格式。不要运行时去拉要钥匙或要付费的 CDN 服务。识字数据包可以在第一次选图片/扫描件时再加载，并在 Service Worker 里缓存；离线且尚未缓存时，用白话说明需要先联网加载一次识别部件。
- 注意 GitHub 项目站路径前缀 `/yanyu-cishu/`（脚本、Worker、数据包都要在这个前缀下能用）。
- 更新 `scripts/build-pages.mjs` 的必需文件清单（以及 Cloudflare 资源构建，如有同类清单），新增资源不得 404。
- 现有测试不要无故变红。补上自动测试：至少覆盖 Excel、Word、PDF（含文字型）、以及从识字后的文本中抽词；准备小的测试夹具，不要塞进大文件。图片识字可用「给定 OCR 文本」测抽取逻辑，再用一两张生成的清晰样张做冒烟（允许注明识别率限制）。
- 不要把本机局域网地址写进页面。
